    Persistent memory for AI agents

    Jul 2026·Designer and builder

    A cross-session RAG memory for a production agent. It improves with use and fades when stale.

    • 1024-d embeddings, int8-quantized into libSQL F8_BLOB columns through a custom Drizzle type.
    • Recall ranked by similarity × 0.95^days, plus a hook that injects the top memories at session start.
    • Weights tuned by agent ratings (EWMA, α = 0.3) and a nightly decay with a ~69-day half-life.
    • Nightly garbage collection, and recalled memories are treated as data, never as commands.

    4other agents adopted it as their memory model

    • TypeScript
    • Turso
    • Drizzle
    • eve
    • Vercel AI SDK

    Distributed Dataset Repository

    Feb – May 2026·Team of 4Code

    A replicated chunk store for AI datasets in Go and gRPC, inspired by the Google File System.

    • Designed for 50+ GB datasets: 64 MiB chunks, 1 MiB CRC32-checked blocks, replication factor 3.
    • I built the master’s failure handling: heartbeats, dead-node detection and automatic re-replication.
    • Chained acks: fsync, wait for downstream, seal, ack upstream. A client ack means every replica persisted.
    • An end-to-end fault-tolerance suite on the Docker Compose cluster stops a node, then corrupts a chunk, and checks each is re-replicated onto the spare node.

    AMRAMKMBPresented to course faculty. About 31% of the hand-written code is mine.

    • Go
    • gRPC

    • BoltDB
    • Docker
